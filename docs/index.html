Guide pas à pas

Connecter une API et créer un CRUD

Un exemple avec des produits pour comprendre comment lire, ajouter, modifier et supprimer des données.

Étape 1

Lancer le projet

Ouvrez un terminal dans le dossier du projet, puis lancez :

npm install
npm run dev

Ouvrez l’adresse affichée dans le terminal, généralement http://localhost:5173.

Étape 2

Connecter votre API

Copiez .env.example dans un nouveau fichier appelé .env. Remplacez l’adresse par celle de votre API :

VITE_API_BASE_URL=https://api.maboutique.fr/api
VITE_API_ENDPOINT_PRODUCTS=/products

Le site va alors demander les produits à https://api.maboutique.fr/api/products. Après une modification de .env, relancez npm run dev.

Mode démo : les pages d’exemple appellent l’API sans jeton. Si votre API exige une connexion, mettez VITE_DEMO_MODE=false et connectez-vous avec un compte de cette API.
Étape 3 · Service API

Créer le service qui parle à l’API

Un service est un fichier JavaScript qui regroupe les requêtes d’une ressource. Dans ce projet, le service partagé existe déjà : src/services/demoResources.service.js. Il utilise src/services/api.js, qui contient l’adresse de base et la configuration Axios.

1. Déclarer les routes. La clé est le nom utilisé par la page, la valeur est la route de l’API :

const ENDPOINTS = {
  produits: import.meta.env.VITE_API_ENDPOINT_PRODUCTS || '/products',
  commandes: import.meta.env.VITE_API_ENDPOINT_ORDERS || '/orders',
  clients: import.meta.env.VITE_API_ENDPOINT_CUSTOMERS || '/customers',
}

2. Ajouter les fonctions de lecture et d’écriture. Elles reçoivent le nom de la ressource et construisent la requête HTTP :

export default {
  async lister(ressource, params = {}) {
    const reponse = await api.get(endpoint(ressource), { params })
    return normaliserListe(reponse, params)
  },
  async creer(ressource, donnees) {
    const reponse = await api.post(endpoint(ressource), donnees)
    return enveloppe(reponse)
  },
  async modifier(ressource, id, donnees) {
    const reponse = await api.put(endpoint(ressource, id), donnees)
    return enveloppe(reponse)
  },
  async supprimer(ressource, id) {
    const reponse = await api.delete(endpoint(ressource, id))
    return enveloppe(reponse)
  },
}

api.get lit, api.post crée, api.put modifie et api.delete supprime. Le service transforme aussi les réponses pour que la page puisse utiliser une liste et sa pagination.

Pour brancher une nouvelle ressource, ajoutez son chemin dans ENDPOINTS, par exemple categories: '/categories'.

Étape 4 · Les requêtes

Faire les quatre actions du CRUD

CRUD veut dire créer, lire, modifier et supprimer. L’API doit fournir ces quatre routes. Chaque réponse de liste doit contenir les champs affichés et un id unique.

Exemple d’un produit :

{ "id": 1, "name": "Cahier", "category": "Papeterie", "price": 3.5, "stock": 20 }

Une liste paginée peut avoir cette forme :

{ "data": { "elements": [{ "id": 1, "name": "Cahier", "category": "Papeterie", "price": 3.5, "stock": 20 }], "pagination": { "page": 1, "par_page": 10, "total": 1, "total_pages": 1 } } }
1 · LIRE

Afficher la liste

GET /products

Dans DemoResourceView.vue, created() lance charger(). La méthode appelle le service, puis range le résultat normalisé dans lignes et pagination.

const resultat = await demoResourcesService.lister(this.ressource, {
  page: this.page,
  par_page: this.taillePage,
  recherche: this.recherche || undefined,
})
this.lignes = resultat.elements
this.pagination = resultat.pagination

La fonction normalise les formats courants. Adaptez-la si votre API renvoie, par exemple, { "items": [], "total": 0 } au lieu de data.elements.

2 · CRÉER

Ajouter un produit

POST /products

Le bouton « Ajouter » lance ouvrirFormulaire(), qui vide les champs configurés. v-model garde la saisie dans formulaire, puis enregistrer() l’envoie :

{ "name": "Cahier", "category": "Papeterie", "price": 3.5, "stock": 20 }
await demoResourcesService.creer(this.ressource, this.formulaire)
this.modalOuverte = false
await this.charger()

Le corps doit contenir les champs attendus par l’API. Après le succès, le formulaire se ferme et le tableau est actualisé.

3 · MODIFIER

Mettre à jour un produit

PUT /products/1

modifier(ligne) copie les valeurs configurées dans formulaire, conserve l’identifiant dans indexModification et ouvre la fenêtre :

this.indexModification = ligne.id
this.formulaire = Object.fromEntries(
  this.configuration.champs.map((champ) => [champ.cle, ligne[champ.cle] ?? '']),
)
this.modalOuverte = true

À l’envoi, enregistrer() choisit modifier() et le service envoie PUT /products/1 avec les nouvelles valeurs.

4 · SUPPRIMER

Retirer un produit

DELETE /products/1

Le bouton demande une confirmation. Après validation, supprimer() envoie l’identifiant mémorisé dans ligneASupprimer, puis actualise la liste :

await demoResourcesService.supprimer(
  this.ressource,
  this.ligneASupprimer.id,
)
this.ligneASupprimer = null
await this.charger()
Résumé : la page appelle le service, le service contacte l’API, puis la page affiche la réponse.
Étape 5 · Page Vue

Relier le formulaire et le tableau au service

Dans src/views/demo/DemoResourceView.vue, CONFIGURATIONS.produits déclare les colonnes et les champs. La valeur cle doit être le nom attendu par l’API :

produits: {
  colonnes: ['Nom', 'Catégorie', 'Prix', 'Stock'],
  champs: [
    { cle: 'name', label: 'Nom du produit' },
    { cle: 'category', label: 'Catégorie' },
    { cle: 'price', label: 'Prix', type: 'number' },
    { cle: 'stock', label: 'Stock', type: 'number' },
  ],
}

Le composant parcourt ces champs avec v-for et v-model="formulaire[champ.cle]". Les lignes de la réponse sont affichées dans le tableau ; CLES_COLONNES relie chaque titre aux clés de réponse, par exemple Prix à price ou prix.

Au chargement de la page, created() appelle charger(). Les méthodes de création, modification et suppression rappellent ensuite charger() pour voir la réponse de l’API.

Exemple de changement de nom : si votre API attend nom, remplacez cle: 'name' par cle: 'nom' dans la configuration et adaptez la colonne dans CLES_COLONNES.

Étape 6 · Navigation

Ajouter la ressource au menu

Exemple : ajouter une page « Catégories ». Faites ces trois changements :

  1. Ajoutez categories: '/categories' dans ENDPOINTS du service.
  2. Ajoutez la configuration categories dans CONFIGURATIONS de la vue, avec les noms de colonnes et de champs de l’API.
  3. Ajoutez ce lien dans menuDemo de src/layouts/TheSidebar.vue : { route: 'demo-ressource', params: { ressource: 'categories' }, libelle: 'Catégories', icone: 'liste' }.

La route Vue demo/:ressource existe déjà : elle réutilise le même écran et le même CRUD pour chaque ressource.

Étape 7 · Vérification

Vérifier chaque action

  1. Ouvrez le navigateur, puis l’onglet Réseau (Network).
  2. Ouvrez la page Produits : vérifiez la requête GET /products et les lignes reçues.
  3. Ajoutez un produit : vérifiez POST /products, puis sa présence dans la liste.
  4. Modifiez ce produit : vérifiez PUT /products/{id} et la nouvelle valeur.
  5. Supprimez-le : vérifiez DELETE /products/{id} et sa disparition de la liste.

Une réponse 401 indique une connexion nécessaire, 422 des champs invalides, 404 une route inconnue. Une erreur CORS doit être corrigée dans la configuration de l’API.

Étape 8 · Partage

Partager le code avec Git

Une fois le projet relié à votre dépôt GitHub, envoyez vos changements avec :

git add .
git commit -m "Ajout de mon CRUD"
git push
Important : partagez .env.example, mais jamais le fichier .env. Chaque personne doit indiquer son propre domaine d’API.

Si ça ne fonctionne pas

Le tableau est vide : vérifiez que GET /products renvoie bien une liste.

Erreur 404 : vérifiez le domaine et la route dans .env.

Erreur CORS : l’API doit autoriser l’adresse de votre site.

La modification échoue : chaque produit doit avoir un id.
